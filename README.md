# Ramp: private Garmin training dashboard (GitHub Pages + phone app)

A static site that GitHub Actions rebuilds from your Garmin Connect data. Open it on your phone, add it to
the home screen, and it behaves like an app.

- **Athlete stats**: interactive charts for training volume, load (acute vs chronic), resting HR, HRV, sleep phases, body battery, VO2max, weight/body composition and strength frequency. Table view on every chart.
- **Activities**: the last 7 days. Tap one for the full Garmin-style breakdown (stats, HR/pace/power/elevation charts, HR zones, laps, route outline, strength sets).
- **Planned training**: the next 7 days, regenerated by Claude every morning from your recent activities and current recovery. Includes run pace breakdowns, strength exercises and Zwift `.zwo` export.

| When (Europe/Berlin) | What |
|---|---|
| 06:15 Mon-Fri, 08:00 Sat-Sun | Full run: sync Garmin, new plan, redeploy |
| Every 3 h, 10:00-22:00 | Data-only refresh (new activities appear, plan untouched) |
| Manual / push to `main` | Run it from the Actions tab (choose `full` or `data`) |

## How the "password protection" works (read this)

GitHub Pages cannot do server-side logins. So the site is split in two:

- The app shell (HTML/JS/CSS) is public but contains **no data**.
- Your data is one encrypted file (`data.enc`, AES-256-GCM, key from PBKDF2-SHA256 with 600,000 rounds of `username + password`). The browser asks for the username and password, decrypts it on your device, and caches the derived key (never the password) so the installed app opens without asking again.

Consequences:

1. The encrypted files are public too (`data.enc` on the site, `state/state.enc` in the repo). Anyone can download them and try guessing offline. **Use a long passphrase** (4+ random words, 16+ characters). A weak password is the only real weakness here.
2. The username is part of the key, not a separate login check. Both must match exactly (case-insensitive username).
3. If you change the password, update the `SITE_PASSWORD` secret and run the workflow; old phones will ask to sign in again.
4. If you'd rather keep the repo private, GitHub Pro/Team can publish Pages from a private repo. Nothing else changes.

## Setup (about 20 minutes)

### 1. Repo and Pages
1. Create a GitHub repo (e.g. `ramp`) and push this folder to `main`.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**

### 2. Secrets (Settings → Secrets and variables → Actions)
| Secret | Value |
|---|---|
| `SITE_USERNAME`, `SITE_PASSWORD` | What you'll type on the phone. Long passphrase. |
| `ANTHROPIC_API_KEY` | From console.anthropic.com. Billed per use, separate from your claude.ai plan. |
| `GARMIN_EMAIL`, `GARMIN_PASSWORD` | Your Garmin Connect login (needs a password; Google/Apple-only sign-in won't work). |
| `GARMIN_TOKENS_B64` | Only if you use MFA or logins get blocked: run `python scripts/garmin_login.py` on your computer once and paste its output. |

Optional repository **variable** `ANTHROPIC_MODEL` to change the planning model (default `claude-sonnet-5-5`; a Haiku model is cheaper).

### 3. First run
**Actions → Refresh Ramp → Run workflow → mode `full`.** The first run backfills the last 30 days of sleep/HRV/resting HR (a couple of minutes; it paces itself to avoid Garmin rate limits). Later runs only fetch what's missing, so the recovery charts grow by a day each morning. Want more history? Run the workflow manually with a larger `backfill_days` (e.g. 90); expect it to take longer.

### 4. Install on your phone
Open `https://<your-username>.github.io/<repo>/`, sign in, then:
- **iPhone (Safari)**: Share → *Add to Home Screen*.
- **Android (Chrome)**: menu → *Install app* / *Add to Home screen*.

### 5. Tell the coach about your life
Edit `config/athlete.json` on GitHub: goal, days per week, `constraints` (events, travel, injuries, fixed sessions), optional `ftp_watts` and `run_threshold_pace`. The next morning's plan respects it.

## Good to know
- **Garmin has no official personal API.** This uses the unofficial `garminconnect` library, which logs in like the Garmin app. Garmin changed its login in March 2026 and could do so again; if syncs start failing, update the library (`scripts/requirements.txt`) or regenerate `GARMIN_TOKENS_B64`. A failing endpoint is skipped and shown in a banner in the app; a failing login fails the run and keeps the last good site online.
- **Sync your watch before 06:15.** The morning plan uses last night's sleep and HRV, which only reach Garmin Connect once your watch has synced with your phone. If it hasn't, the planner works from the days it has.
- **If the plan call fails**, the previous plan stays and the Plan tab shows a banner.
- **GitHub cron drifts** by 5-30 minutes and uses UTC; the workflow lists both winter and summer slots and only runs the one that lands in the right Berlin hour.
- **Preview without Garmin**: `python scripts/demo_data.py && python scripts/assemble.py`, copy `site/*` to `dist/`, then `SITE_USERNAME=demo SITE_PASSWORD=demo node scripts/crypt.mjs encrypt build/data.json dist/data.enc` and serve `dist/` with `python -m http.server`.

## Layout
```
site/        the PWA (index.html, app.js, charts.js, crypto.js, sw.js, manifest, icons)
scripts/     sync_garmin.py, plan.py, assemble.py, crypt.mjs, garmin_login.py, demo_data.py
config/      athlete.json (you edit), salt.txt (public, keeps phone keys valid)
state/       state.enc (encrypted history, committed by the workflow)
.github/workflows/refresh.yml
```
